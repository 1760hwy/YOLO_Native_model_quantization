# 消融实验报告：RDK X5 BPU 端侧部署三阶段优化策略

## 一、实验背景

本实验围绕自有 YOLO11 火焰检测模型在 RDK X5 BPU（Bayes-e）上的端侧量化部署，对三项关键优化策略进行逐项消融验证，揭示每项策略的独立贡献与相互依赖关系。

---

## 二、三项优化策略

| 策略编号 | 策略名称 | 针对的根因 |
|---------|---------|-----------|
| ① | INT16 Softmax 精度提升 | Softmax CPU 回退导致计算图拆分、帧率骤降 |
| ② | 形状驱动输出契约对齐 | hb_mapper 输出顺序隐式漂移导致解码失败 |
| ③ | 校准输入一致性约束 | 校准集与推理输入存在语义失配，logit 分布压缩至负区间 |

---

## 三、消融配置矩阵

| 配置 | INT16 Softmax | 形状驱动解码 | 校准一致性 | FPS | mAP@0.5 | 失效原因 |
|-----|:---:|:---:|:---:|:---:|:---:|--------|
| **A（基线）** | ✗ | ✗ | ✗ | 20.5 | 0% | Softmax CPU 瓶颈 + 校准错误 |
| **B** | ✓ | ✗ | ✗ | 49.2 | 0% | 固定索引解码失败（IndexError）|
| **C** | ✓ | ✓ | ✗ | 49.2 | 0% | 校准失配 → fire logit 被压缩 |
| **D** | ✓ | ✗ | ✓ | 49.2 | 0% | 固定索引解码仍然失败 |
| **E（完整方案）** | ✓ | ✓ | ✓ | **49.2** | **68.3%** | — |

**核心结论：三项策略存在串联依赖——任一缺失均导致部署完全不可用（mAP=0 或 FPS<30）。**

---

## 四、逐项策略分析

### 策略①：INT16 Softmax 精度提升

- **对照**：Config A（INT8，CPU 回退）vs Config B（INT16，BPU 完整子图）
- BPU 推理时延：36.13 ms → 9.69 ms（降幅 **73%**）
- 端到端帧率：20.5 FPS → 49.2 FPS（提升 **×2.4**）
- C2PSA 注意力模块内的 Softmax 运算在 INT8 精度下强制回退 CPU 执行，导致单一 BPU 子图被拆分为 BPU+CPU 双子图，DMA 数据搬运引入额外 26.4 ms 开销。选择性提升为 INT16 后，Softmax 维持在 BPU 上执行，子图合并。

### 策略②：形状驱动输出契约对齐

- **对照**：Config B（固定索引）vs Config C（形状驱动）
- 固定索引在真实编译输出（自然顺序）下解码成功率：**0%**
- 形状驱动在自然顺序与任意重排下解码成功率：**100%**
- hb_mapper 编译输出顺序不保证与 ONNX 模型一致。bbox 分支通道数=64（=4×reg_max），cls 分支通道数=1（单类检测），通过通道维度唯一标识张量语义，与输出顺序完全无关。

### 策略③：校准输入一致性约束

- **对照**：错误校准（Config C/D）vs 规范校准（Config E）
- 错误校准：logit 均值 −15.66，最大值 −10.29，无法产生任何有效检测框（0 帧）
- 规范校准：logit 最大值恢复至正区间 +0.26，mAP@0.5 = **68.3%**（vs 浮点基线 71.7%，量化损失仅 **3.4 pp**）
- 校准集须与部署配置在颜色空间（NV12）、张量布局、数值范围上完全一致，归一化仅在 YAML scale_value 中执行一次。

## 五、流式推理性能测试（扩展数据，300 s 连续压力测试）

| 指标 | RTSP 2304×1296@15fps | USB 640×480@30fps |
|-----|:---:|:---:|
| 预处理 | 7.9 ms | 5.0 ms |
| BPU 推理（实际） | 9.5 ms | 9.5 ms（*）|
| 后处理 | 2.8 ms | 6.9 ms |
| E2E 平均延迟 | **20.3 ms** | 25.9 ms |
| P95 延迟 | 21.7 ms | 33.2 ms |
| 推理吞吐 | 49.3 FPS | 38.7 FPS |
| 实际视频帧率 | 14.3 FPS | 25.7 FPS |
| 掉帧率 | **4.4%** | 14.3%（†）|
| 稳定性 | 无崩溃 | 无崩溃 |

（*）USB 场景计时偏高（13.9 ms）源于 V4L2 驱动帧缓冲拷贝及 DDR 带宽竞争；BPU 纯推理时延恒定约 9.5 ms。  
（†）掉帧率过高非算力瓶颈（38.7 FPS > 30 FPS），可通过采集-推理线程异步缓冲优化改善。

## 九、论文结论模板

> 本文对三项端侧部署优化策略（Softmax 精度提升、形状驱动输出对齐、校准输入一致性约束）进行了系统性消融实验。实验结果表明，三项策略存在串联依赖关系：任一缺失均导致模型在 RDK X5 BPU 上完全不可用（mAP@0.5 = 0% 或 FPS < 30）。本文完整方案（Config E）实现端到端平均延迟 20.3 ms、推理吞吐 49.2 FPS、mAP@0.5 = 68.3%（量化损失 3.4 pp），是五组配置中唯一同时满足实时性（> 30 FPS）与检测可用性（mAP > 0）要求的方案。扩展的 300 s 流式压力测试进一步验证了系统稳定性（RTSP 场景掉帧率仅 4.4%）。
